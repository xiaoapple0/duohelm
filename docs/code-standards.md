# 代码规范

## 验收标准

任何改动在合并之前，都要拿出以下检查的结果。每项已运行的检查附上它实际输出的内容；没有运行的检查，明确写"未运行"以及原因。

1. **有一个没有这次改动就会失败的测试。** 关键逻辑（量化正确性红线、安全边界，范围见 AGENTS.md 的“审查和验证的范围”）的改动，要回退或破坏一次，运行新测试，确认它真的失败；恢复后确认它通过。其他改动不要求做这一步。只改文档、文案的改动不需要新测试。
2. **测试在沙箱里运行。** 测试只用 `tmp_path` 和测试夹具里的数据目录，绝不触碰 `~/.duohelm`、真实凭据或真实账户。
3. **后端检查。**
   ```bash
   set -o pipefail
   uv run ruff check .
   uv run ruff format --check .
   uv run pyright
   uv run pytest <相关测试>  # 本地只跑和改动相关的测试，全量交给 CI；PR 说明里写明本地跑了哪些
   ```
4. **前端检查**（改动 `web/` 时）。
   ```bash
   cd web && npm ci && npm run typecheck && npm run build
   ```
   涉及交互流程的改动，运行相关的 Playwright 测试（M1 起引入）。
5. **量化正确性检查**（触及数据、因子、回测逻辑时）。
   - 未来函数扰动测试通过（`duohelm_sdk.checks.check_no_lookahead`）
   - 黄金数据集上的结果没有变化；如有变化，提交正文写明原因
6. **真实使用。** 涉及外部数据源或券商的改动，用真实服务在沙箱环境里验证。做不到就明确说明。

## 合并条件

- 把 PR 拉到本地，合并到当前 `main` 上，对**合并后的结果**跑上面的检查。只读 diff 不算审查。
- 合并命令锁定审查过的那个 commit：`gh pr merge --match-head-commit <sha>`。
- 合并前在 PR 里写下审查记录：审查的 commit、运行了哪些检查、结果如何。

## 发版条件（全部满足）

- 被 tag 的 commit（或包含它的更新 commit）上，CI 已跑完并通过。被取消的运行不算通过。
- tag 是 `origin/main` 的祖先。
- 修复攒批发布，只增加测试的改动不单独发版。

## 主要规则

### 范围与正确性
- 每个改动只做它的目标需要的事。无关的重构、新功能放进单独的 PR。
- 验证完整路径：从输入，经过调用方、状态，到副作用。
- 修复覆盖所有同类代码路径。
- 测试改动触及的边界：交易日边界、停牌、缺失值、空股票池、各个平台。

### Python
- 所有公开函数有类型标注，pyright 严格模式无错误。
- 数据处理用 polars 向量化表达式，不写逐行循环。
- 时间统一用 `datetime.date`（日频）或带时区的 `datetime`（分钟级），不用字符串表示日期。
- 不在库代码里 `print`，用 `logging`。

### TypeScript
- `strict` 模式，不用 `any`。
- 后端接口类型从 OpenAPI 生成，不手写重复的类型。
- 用户可见的文字集中管理，便于将来做多语言。

### 测试
- 每个修复都带一个没有它就会失败的测试。
- 依赖缺失时测试可以在本地跳过，但在 CI（`CI` 环境变量存在）上必须失败。静默跳过的测试等于没有测试。
- 测试用例使用真实形态的数据：停牌、缺失字段、复权跳变、新股、退市股。
- 测试断言行为，不断言实现细节。
- 测试不访问网络。

### 审查
- 在当前 `main` 上运行 PR，而不是相信 PR 的描述或它自己的 CI。
- 关键逻辑（量化正确性红线、安全边界）的改动，故意破坏被保护的代码，确认测试能抓住。
- 维护者刻意做出的产品决定，审查者不推翻。
- `main` 上失败的测试不是基线，是要立刻修的 bug。

### 提交信息
- 写明改动的区域、用户可见的行为变化、对应的 issue，以及怎么验证的、哪个测试在没有改动时会失败。
