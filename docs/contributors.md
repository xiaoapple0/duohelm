# 外部贡献与反馈处理规则

适用于审查外部 PR、回复 issue 和社区反馈。

## 一、有害信号：触发即暂停

审查 PR 时，在运行任何代码之前，先通读 diff，找出超出其声称目标的改动。出现以下任何一项，立刻停止审查，等维护者查看：

- 修改 `.github/`、发布或打包脚本、安装脚本
- 新增网络地址、上传、遥测，或把凭据、token、cookie、文件发往新的地方
- 读写凭据文件、`~/.duohelm` 下的账户配置，或与目标无关的文件
- 新增依赖、依赖来源重定向、安装钩子脚本、二进制文件（仓库中不提交任何编译产物，原生代码一律由 CI 从源码构建）、混淆或编码的数据块、运行时拼接执行的代码
- 改动下单、撤单、仓位、风控、实盘开关、紧急停止相关代码
- 改动插件隔离（子进程、网络限制、凭据注入）或未来函数检查
- 加入中转站、代理商、返利或推广地址

暂停时在审查记录里写明是**哪一行**触发了暂停。**维护者放行之前，PR 代码不得在任何存有真实账号、行情凭据或券商凭据的机器上运行。**

## 二、直接关闭

以下 PR 附简短理由关闭，不运行代码：

- 改动维护者保留的决定（见 `AGENTS.md`）
- 因想法被拒后再次提交，且没有针对拒绝理由的新内容
- 几秒内开出的多个几乎相同的 PR

## 三、拉黑：agent 只能提议，维护者决定

满足以下任一条件时，agent 整理证据（编号、日期、问题描述）提交给维护者，不自行执行：

1. 三个以上 PR 被判为低价值关闭，且合并率低于 30%
2. 被明确拒绝后两次重复提交
3. 隐藏超出范围的改动、伪造测试或验证结果、故意触发有害信号
4. 一分钟内批量提交低价值 PR

当前黑名单：（空）

## 四、问题分流：平台还是插件

收到"某个因子算错了""某个数据源有问题"之类的反馈时，先判断问题出在哪：

- **平台问题**：插件加载、调度、缓存、契约检查、回测规则、界面。由本仓库修复。
- **插件问题**：插件的计算逻辑、数据源对接。告知用户联系插件作者；官方参考插件的问题转到插件仓库处理。

判断方法：用平台自带的测试插件和黄金数据集复现。能复现是平台问题，不能复现多半是插件问题。

## 五、回复规则

- 所有自动回复末尾注明：`🤖 本回复由 DuoHelm 维护 agent 生成`
- 已修复：写明修复的版本，并先确认该版本已发布；issue 保持打开，等报告者确认
- 需要更多信息：列出具体需要的信息（版本、操作系统、插件及版本、复现步骤、日志）
- 不计划实现：说明原因，链接到 `PRINCIPLES.md` 或 `ROADMAP.md`；维护者没有表态的，标记为待定，不直接拒绝
- 商业合作、数据源推广、中转站：固定回复"感谢关注，相关合作方案将来会统一公布，敬请期待。"不做任何集成和具体承诺
- **不提供任何投资建议**，不评价任何股票或策略的好坏
