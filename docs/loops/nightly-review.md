# 每晚回顾任务

建议每天运行一次。目标：从当天的工作里提炼教训，更新 `LESSONS.md`，必要时升级进代码规范。

## 步骤

1. **收集当天的工作**：过去 24 小时合并到 `main` 的提交、关闭和重新打开的 issue / PR、发布的版本。记录提交数、返工数（修复刚合并或刚发布内容的提交）。

   - 自动合并的 PR（AGENTS.md 阶段 3）逐个复查，打了 `auto-merged-high-risk` 的排在最前。发现自动合并的 PR 引入了问题时，按 AGENTS.md “自动暂停”开 issue，暂停自动合并

2. **找出三类问题**
   - **返工**：修复了不久前刚合并的东西，或同一个 issue 被重新打开
   - **不该合并**：带着失败的新测试、已知问题、超出范围的改动，或触及量化正确性红线却没有黄金数据对照
   - **验证太薄**：提交说明里没有验证记录；"main 上也一样失败"未经核实；没有真实使用

3. **归纳成"一类问题"**
   - 已有对应教训：追加证据；如果今天是新的一天，出现次数加一
   - 没有：按模板新增，规则要能套用到下一次类似的情况
   - 做对了的例子，作为"✅ 做对了"追加

4. **升级**：出现次数达到 3 的教训，规则和代表性证据移入 `docs/code-standards.md`

5. **整理**：每条只保留最近几条证据；在"时间线摘要"加一行当天数据

6. **提交**：在独立 worktree 里改动，单独开 PR，标题 `lessons: <日期>`，只改 `LESSONS.md` 和 `docs/code-standards.md`

## 不做的事

- 不修改代码，需要修的问题另开 issue
- 不在教训里点名评价贡献者
- 不推翻维护者保留的决定
