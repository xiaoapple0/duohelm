# 行情与数据

## 职责

- 行情源插件：从外部数据源取数，转换成标准格式
- 平台：校验格式和质量、入库、提供给因子计算和回测

## 标准格式

权威定义：`packages/duohelm-sdk/src/duohelm_sdk/schema.py`。

日频 K 线（`BARS_SCHEMA`）：

| 列 | 类型 | 说明 |
|---|---|---|
| `date` | Date | 交易日 |
| `symbol` | String | 证券代码，A 股用 `600000.SH` / `000001.SZ` / `920000.BJ` 格式（北交所已改用 920 开头的代码） |
| `open` `high` `low` `close` | Float64 | **未复权**价格 |
| `volume` | Float64 | 成交量（股） |
| `amount` | Float64 | 成交额（元） |

复权因子单独存储，在计算时按需应用。原因：前复权价格会随新的除权事件改变历史值，直接存前复权价格会破坏可复现性，也容易引入未来函数。

复权因子（`ADJ_FACTORS_SCHEMA`，SDK 0.2 起）：

| 列 | 类型 | 说明 |
|---|---|---|
| `date` | Date | 除权除息日 |
| `symbol` | String | 证券代码 |
| `factor` | Float64 | **累计后复权比例**，自 `date` 当天起生效，直到下一行；第一行之前视为 1.0 |

- 后复权价 = 未复权价 × factor(t)；以 T 日为基准的前复权价 = 未复权价 × factor(t) / factor(T)
- 因子只能由 `date` 及以前的事件和行情决定，不得用之后的数据归一化
- 计算方法（`duohelm_sdk.adjust.factors_from_events`）：每个事件取除权日**之前**最近的收盘价 P，除权参考价 = (P − 每股派现 + 配股价 × 每股配股数) / (1 + 每股送转 + 每股配股数)，比例 = P / 参考价，按日期累乘。有测试守护：截断某日之后的事件或行情，该日及以前的因子不变

证券列表（`SECURITIES_SCHEMA`，SDK 0.2 起）：

| 列 | 类型 | 说明 |
|---|---|---|
| `symbol` | String | 证券代码，唯一 |
| `name` | String | 名称 |
| `exchange` | String | `SH` / `SZ` / `BJ`，与代码后缀一致 |
| `kind` | String | `stock` / `index` |
| `list_date` | Date | 上市日，未知时为 null |
| `delist_date` | Date | 退市日（最后一个交易日），仍在市时为 null |

`exchange` 和 `kind` 以后可能新增取值：使用方遇到不认识的取值要跳过这一行，不能报错（`schema.known_securities()`）。

能直接列出退市证券的数据源（如 xtdata）在 `Capabilities.lists_delisted` 中声明，平台直接取完整名单；不能的（如 eltdx），平台用 `lookup_securities` 扫描代码区间。

## 主数据源：eltdx（M1 决定）

**主数据源为 [eltdx](https://github.com/electkismet/eltdx)**（通达信协议的 Python 库，核心由 Rust 实现；2026-11-25 用 3.3.5 版实测）。M1 不考虑其他数据源。行情源插件放在独立的插件仓库 `duohelm-plugins`，平台本身不依赖 eltdx。

### 许可限制

eltdx 的许可是“非商业学习与数据研究”：

- 只允许个人学习、数据接口与格式研究及非商业用途
- 禁止把 eltdx、衍生作品**或通过它获取的数据**用于商业活动、付费服务、生产服务、转售、营利性数据服务、**自动化交易服务**
- 访问第三方服务器须自行遵守相关法律法规和服务协议

对本项目的影响：

- M1–M5（行情、股票池、因子、研究、回测）属于个人非商业研究，在许可范围内
- **M7 实盘之前必须重新确认许可**：用 eltdx 获取的数据驱动自动下单，可能落入“自动化交易服务”的禁止范围。M6 模拟盘开始前也应先确认
- 项目将来如果开放给其他用户、提供服务或涉及任何收费，都必须先重新评估数据源

### 实测结论（eltdx 3.3.5，2026-11-25）

| 项目 | 结果 | 平台的处理 |
|---|---|---|
| 日线最早年份 | 上证指数从 1990-12-19 开始，个股从上市首日开始（平安银行 1991-04-03）；北交所现用 920 开头的代码，历史从 2020-12-23 开始 | 首次全量导入从上市首日开始，不设起始年份 |
| 退市股票 | 普通 K 线接口对退市股返回空；专用的退市日线接口能取到完整的未复权历史（测试的 8 只都能取到，最早的退市于 2002 年）。**代码表只有在市股票，没有退市名单** | 首次导入时扫描 A 股代码区间，发现退市股；之后每天对比代码表，发现新退市的股票 |
| 复权 | 服务器的复权价是“未复权价 × 系数 + 偏移”的线性变换，前复权早期价格会出现负数（平安银行最早为 −3.51） | 不使用服务器复权价。平台存未复权价，并根据除权除息记录在本地计算按比例的复权因子 |
| 停牌 | 历史停牌日**没有这一行**；当前停牌的股票当天会多出一根成交量为 0、价格等于前收盘价的占位 K 线 | 入库时丢弃成交量为 0 的行；“某个交易日没有这一行”即表示当天不可交易 |
| 交易日历 | 没有专门的接口，eltdx 自己也是用基准指数的日线推出来的。1991 年深市周六开市，上证指数推出的日历里没有这些日子；2000 年以后沪深两市完全一致 | 按交易所分别用指数日线推出日历：上海用 `sh000001`，深圳和北京用 `sz399001` |
| 历史指数成分 | 只有当前成分名单和纳入日期，**没有调出记录**，无法得到历史成分 | 从 M1 开始每天保存成分快照；之前的历史成分属于已知缺口（见下） |

## 存储（M1）

源码：`packages/duohelm/src/duohelm/storage/`。数据根目录是 `$DUOHELM_HOME/data`（默认 `~/.duohelm/data`）：

```
data/
  files/<数据集>/<分区>/<sha256>.parquet   数据文件，按内容命名，写好后从不修改
  manifests/<快照 id>.json                每个快照一份清单
  catalog.db                              快照、当前快照指针、钉住的快照、退市股扫描记录（SQLite）
```

| 数据集 | 格式 | 主键 | 分区 |
|---|---|---|---|
| `bars_1d` | `BARS_SCHEMA` | symbol、date | 按 date 的年份 |
| `adj_factors` | `ADJ_FACTORS_SCHEMA` | symbol、date | 不分区 |
| `securities` | `SECURITIES_SCHEMA` | symbol | 不分区 |
| `calendar` | market、date | market、date | 不分区 |

### 只新增文件

- 每次写入生成新的 Parquet 文件，已有的文件从不修改。修改和删除都通过追加新文件完成
- 每个文件多一列 `_deleted`：为 True 的行是**删除标记**，表示这个主键的数据作废（其余列为 null）
- 读取时按清单里的文件顺序合并：同一个主键以最后出现的为准，最后去掉删除标记
- 写入前先和当前快照比对，只写入新增或变化的行；删除标记也只写给当前存在的主键。所以重复写入同样的数据不会产生新文件，也不会产生新快照
- 写文件时先写临时文件、落盘（fsync），再按内容的 sha256 改名。同样内容的文件只存一份
- 分区列必须是主键的一部分，这样同一个主键的所有版本都在同一个分区里

### 快照

- 清单是规范化的 JSON（键排序、无多余空白），按顺序列出每个数据集生效的文件及其 sha256、行数和分区。**清单的 sha256 就是快照 id**：内容相同，id 相同，与写入的机器和数据集的写入顺序无关（前提是 polars 版本相同，Parquet 编码一致）
- `catalog.db` 记录每个快照的父快照、创建时间、产生它的任务和统计，以及当前快照指针
- 提交用乐观锁：切换当前快照时，指针必须仍等于写入开始时的快照，否则抛 `SnapshotConflictError`，这次写入的新文件被删除
- 研究和回测记录所用的快照 id，并把它**钉住**（`catalog.pin`），之后按同一份清单读取，结果可以复现

### 整理与清理

- **整理**（`compact`）：把一个数据集每个分区的多个文件合并成一个，同时消化删除标记。生效数据不变，产生一个新快照；旧快照照样能读
- **清理**（`gc`）：保留当前快照、钉住的快照和 `keep_days` 天内创建的快照，其余快照的清单删除并标记为已清理；不被任何保留快照引用、且修改时间早于 `min_file_age_s` 的数据文件删除（默认 24 小时，给正在写入、尚未提交的事务留出时间）

### 退市股扫描记录

不能直接列出退市证券的数据源（`Capabilities.lists_delisted` 为 False），平台用 `lookup_securities` 扫描代码区间。每个扫过的代码（无论有没有找到）都记进 `catalog.db` 的 `security_scan` 表，不随快照变化，之后不再重复扫描（`catalog.unscanned()`）。扫描的代码区间和扫描流程在同步任务中实现。

元数据（任务等）仍在 `$DUOHELM_HOME/duohelm.db`；行情的目录库单独放在 `data/catalog.db`，两者的表结构版本互不影响。

## Point-in-time 要求

| 数据 | 必须按什么时间对齐 |
|---|---|
| 复权因子 | 除权除息日 |
| 指数成分股 | 调入、调出生效日 |
| 财务数据 | 公告日，不是报告期 |
| 行业分类 | 分类变更生效日 |
| ST 标记 | 实施日 |

## 已知缺口

- 存储与快照已实现，入库时的质量检查（OHLC 一致性、停牌占位行等）随同步任务实现
- 主数据源 eltdx 不提供历史指数成分（没有调出记录）。M1 之前的指数股票池无法做到 point-in-time，用它回测会有幸存者偏差
- eltdx 的行情连接由 Rust 原生代码发起，M0 的 Python 层网络拦截管不到它，清单里的网络权限目前只是声明（见 plugins.md 和 #7）
